why this one

A sandbox should be a receipt, not a relationship.

Most sandboxes want an account, an API key and a promise. This one wants a signed payment and a public key.

The payment is the identity

POST /v1/sessions answers 402 with a price. A signed x402 payment becomes the entitlement and the receipt. No account, no key, no signup.

One payment, one session. Replay returns the same session.

The API moves ciphertext

Commands and files are sealed to the guest's ephemeral key. The API, controller and relay route opaque frames and never hold a decryption key.

Not confidential computing. There is no hardware root of trust.

The lease is the only clock

A guest watchdog, the controller deadline and activeDeadlineSeconds each enforce it. When the lease ends, the pod and its memory-backed workspace are deleted.

Destroy is idempotent. Nothing survives termination.

the whole protocol

Four moves. One small VM.

No install, no daemon, no teardown script. Ask, pay, run, forget.

  1. 01

    Ask

    The client posts a session spec and its X25519 public key. The API answers with a price for that exact spec.

    POST /v1/sessions
→ 402 PAYMENT-REQUIRED
  2. 02

    Pay

    The client signs the requirement and retries. Settlement is bound to a specHash, so a retry cannot charge twice or swap the machine.

    PAYMENT-SIGNATURE: <base64>
→ 201 · capability · session
  3. 03

    Run

    The controller starts one Kata microVM, from the warm pool or cold. Commands travel inside a sealed envelope with an idempotency key.

    { op: "exec",
  command: ["python3", "app.py"] }
  4. 04

    Forget

    Results come back sealed to the client. The lease ends, the pod is deleted, the workspace disappears. There is no cleanup step to forget.

    DELETE /v1/sessions/{id}
→ 200 · TERMINATING

three ways in

Pick the smallest handle.

The CLI and SDK build the payment and sealed envelopes for you. If you are writing an agent, use one of them. Do not hand-roll the cryptography.

cli one shot

docs 
sandbox run \
  --file data.csv=data.csv \
  --file analyze.py=analyze.py \
  --return out.csv \
  --json \
  -- python3 analyze.py

Creates a fresh session, uploads, runs, downloads, destroys. --json gives an agent something stable to parse.

ts sdk

docs 
const run = await client.run({
  command: ["python3", "analyze.py"],
  files: { "analyze.py": source },
  returnFiles: ["out.csv"],
  tier: "short",
});
console.log(run.exitCode, run.stdout);

Always destroys the session, even when the command fails. Files are workspace-relative.

http raw

docs 
POST /v1/sessions
GET  /v1/sessions/{id}
POST /v1/sessions/{id}/operations
GET  /v1/sessions/{id}/operations?request=…
DELETE /v1/sessions/{id}

Every session call carries X-Sandbox-Capability. Operations are sealed envelopes, not plaintext JSON.

on your laptop

Two minutes to your own.

The demo buys a session, runs a command, uploads a file, downloads a result and destroys the VM. Same API, relay and guest as a real deployment.

Local cluster

make up            # kind + Cilium + images + deploy
make demo-session  # pay, create, exec, upload, download
make down

Needs Docker, kind, kubectl, the Cilium CLI, Node 24+ and Go 1.26+. Local clusters use runc, not microVMs.

No cluster

npm ci
make verify  # typecheck, structure lint, unit + property
make test    # adds integration against the guest binary

Most of the system is testable in under a minute. make security-test needs a live cluster and runs the packet-level isolation suite.

!

This is an alpha reference deployment, not a hosted service. Payments are mock or testnet, there is no hardware attestation, and checkpoints are plaintext on disk. What is missing, in order.

the honest bit

What holds, and what does not.

Every claim below has a test or a doc behind it. The gaps are listed with the same care as the guarantees.

✓ Holds today

  • The lease ends on time: guest watchdog, controller deadline and Kubernetes each enforce it
  • Commands and files stay sealed in transit; the API, controller and relay only route ciphertext
  • One Kata microVM per session, on tainted, default-deny nodes
  • The guest dials out to the relay; egress only through an allowlisting proxy on 443
  • No inbound sandbox networking

× Does not, yet

  • No hardware root of trust: the dev attestation key ships in the repo
  • Suspended workspace checkpoints are plaintext on disk, readable by the storage admin
  • Mock or testnet payments only, no mainnet
  • No GPUs, no arbitrary OCI images, no memory snapshots
  • Not feature parity with a general-purpose sandbox platform

Read the guarantee matrix and threat model before repeating any of this as a security claim.
