# Committed benchmark results

Every directory here is a run that produced a number used in the docs. Runs are
generated by `benchmarks/harness/cli.ts` and are never edited by hand.

## Canonical runs

These back the figures in [`docs/performance-cluster.md`](../../docs/performance-cluster.md)
and [`docs/engineering-notes.md`](../../docs/engineering-notes.md):

| Directory | What it measures |
| --- | --- |
| `cluster-startup-*` | warm and cold create → ready → exec → destroy, on the two-node Talos cluster |
| `cluster-exec-*` | existing-session exec latency |
| `cluster-burst-*` | 25 simultaneous creates against the pool |
| `cluster-hold-*` | concurrent held sessions |

Timestamps in the directory name are UTC; the suffix is the commit the harness
ran against. To reproduce, check out that commit, run `make up`, then the
matching `make benchmark-*` target. See
[`benchmarks/README.md`](../README.md).

## Local and development runs

`baseline-*`, `final-*`, `load-*`, `optimized-*` and timestamped directories
without a `cluster-` prefix come from the kind rig. They are useful for
regressions and for the analysis scripts, but they are not the numbers quoted in
the README — the cluster runs are.

## Format

Each run directory contains:

- `*.jsonl` — one record per sample
- `*.summary.json` — percentiles and counts
- `*.csv` — the same data for spreadsheets and `benchmarks/analysis/`
- `*.meta.json` — scenario config, image tags and limits
- `environment.json` — node shape, runtime class, CNI

If a run is incomplete (aborted, partial samples), delete it rather than leaving
it for someone to mistake for evidence.
